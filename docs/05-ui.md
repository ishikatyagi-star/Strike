# Doc 5 — UI

> Aesthetic: **The Instrument, clarified.** Strike uses a calm MiniMax-inspired light interface for retail intent, while Wavelength uses a warm Shopify-inspired commerce interface.
> Status: APPROVED · Depends on: Docs 1–4 · Last updated: 2026-08-03

## 1. Direction & the stage trick

Strike is light, calm, and precise: a white canvas, quiet gray surfaces, near-black ink, monospace tabular numerals for every amount, and **one signal color (strike green) that is reserved exclusively for money-state changes** — armed, struck, paid. The eye learns in 30 seconds that green = "the mandate acted," which makes Beat 4 land without narration. Restrained blue and coral accents support navigation and emphasis without competing with status colors. Motion remains minimal and functional.

**Wavelength (the merchant) is deliberately warmer and more commerce-led**: cream and white surfaces, black pill actions, aloe and pistachio accents, and softer card geometry. In the demo, cool neutral Strike surfaces and warm Wavelength surfaces remain instantly tellable-apart. The visual boundary *is* the architecture boundary (Doc 4 §2), on screen.

Display insurance: body text meets WCAG AA contrast, focus is visible on every interactive element, controls reach 44 px on touch layouts, and both systems retain hierarchy from 375 px through projector widths. Reduced-motion preferences disable non-essential transitions.

## 2. Design tokens

**Color** (CSS vars; the only place colors are defined):
| Token | Value | Use |
|---|---|---|
| `--bg` / `--surface` / `--surface-soft` / `--line` | `#FFFFFF` / `#F7F8FA` / `#F2F3F5` / `#E5E7EB` | page / cards / quiet sections / hairlines |
| `--ink` / `--muted` | `#0A0A0A` / `#5F5F5F` | text / secondary |
| `--strike` / `--strike-soft` | `#087A55` / `#E8FFEA` | **money states only**: ARMED dot, STRUCK flash, PAID, price-below-cap. Never decoration. |
| `--warn` / `--warn-soft` | `#8A5200` / `#FFF4D8` | expiring, aborted-rearmed |
| `--danger` / `--danger-soft` | `#B4233A` / `#FFF0F2` | DECLINED, failed, revoke |
| `--link` / `--accent` / `--coral` | `#17437D` / `#1456F0` / `#D94727` | links / focus and restrained information / rare emphasis |
| Wavelength set | `#FBFBF5` canvas, `#FFFFFF` surface, `#111111` ink, `#C1FBD4` aloe, `#D4F9E0` pistachio | scoped to `/store`, `/store/admin`, and the Wavelength demo panel |

**Type**: DM Sans (Strike UI) + Geist Mono (all numerals, hashes, timestamps, event names — `font-variant-numeric: tabular-nums` everywhere). Wavelength uses Inter for commerce UI.
Scale: 12 (meta) · 13 (body-dense) · 15 (body) · 18 (section) · 24 (screen title) · 40 (the price) · 56 (hero only).

**Spacing** 4-base: 4/8/12/16/24/32/48/64. **Radius**: Strike cards 16px, compact controls 8px, buttons and badges full-pill; Wavelength cards 12–20px and actions full-pill. **Elevation**: flat hairline cards by default, with only soft tinted shadows for floating panels. **Motion**: 150 ms ease-out for state; the strike cascade is the single exception (staggered 150 ms × 5 timeline steps), and reduced-motion removes non-essential transitions.

## 3. Component list

`StatusBadge` (one per state-machine state, colors above — the state machine made visible) · `ScopeCard` (the signed fields, rendered from the exact draft bytes — Doc 2 §3.2) · `PriceTicker` (mono, 40px, green-flashes when < cap) · `Timeline` (audit events; icons per event_type; live via 2 s cursor poll) · `MandateRow` · `PasskeyButton` (fingerprint glyph, one per app) · `CountdownChip` (time to `valid_until`; amber < 12 h) · `ReceiptBlock` (hash, sig, verify recipe, download) · `DeclineBanner` (danger, shows Prava's raw refusal — Beat 5's hero) · `EmptyState` · Wavelength: `ProductCard`, `AdminLever` (the big red button), `OrderConfirmation`.

## 4. Screens

### S1 · Create mandate — `/new`
**Purpose:** utterance → scope card → passkey (Beat 2). **The one thing that matters:** the **ScopeCard** — every limit the user is about to sign, each field tappable-to-edit; the passkey button sits *below* it so signing visibly follows seeing.
States: *empty* (prompt box + 3 example utterances) · *drafting* (skeleton card, "parsing…") · *review* (card + edit affordances + "what you see is what you sign" caption) · *signing* (OS passkey sheet) · *armed* (badge flip + redirect) · *error* (`PARSE_FAILED` → inline "say it differently or fill the form"; `VALIDATION_FAILED` → the offending field glows danger).

### S2 · Mandate book — `/`
**Purpose:** all mandates, live (Beat 3). **The one thing:** each row's **live price vs cap** pair in mono — `$199.00 / <$180.00` — with the ARMED pulse dot. The screen should read like an open-orders book.
States: *empty* ("No standing mandates." + create CTA) · *loading* (row skeletons) · *live* (armed rows pulse subtly; 2 s poll) · *fired* (row flashes green, badge STRUCK→ moves to top) · *error* (stale-data banner with retry, never a blank screen).

### S3 · Mandate detail — `/m/[id]`
**Purpose:** the life of one mandate (Beats 4–5 both happen here). **The one thing:** the **live Timeline** — the audit log rendered honestly; during execution it cascades: `TRIGGERED → SESSION → TOKEN •••• 4242 → CHECKOUT → PAID $174.00`, each row green as it lands.
States: *armed* (ScopeCard + ticker + countdown + revoke button) · *triggered/executing* (cascade running) · *fulfilled* (receipt CTA) · *aborted-rearmed* (amber event row in place, still armed — the slippage story visible) · *failed/declined* (DeclineBanner with Prava's actual error) · *revoked* (struck-through card) · *expired*.

### S4 · Receipt — `/m/[id]/receipt`
**Purpose:** the trust artifact (Beat 6). **The one thing:** the verification line — `signature ✓ verified against passkey · hash ✓ matches signed fields` — above the money summary, then **Download verifiable receipt (JSON)**.
States: *loading* · *verified* · *verify-failed* (danger — should never happen; if it does we want it loud, not hidden).

### S5 · Wavelength storefront — `/store` (+ `/store/admin`)
**Purpose:** the thing being watched; the lever (Beat 4). **The one thing:** the product price, huge — it's what the whole demo watches. Admin: the red **"Drop price to $174"** preset button (typing $ amounts on stage under nerves is how demos die; presets only).
States: product *in-stock/price* · *order-confirmed* (Beat 4's right-window payoff) · admin *lever + reset*.

### S6 · Demo cockpit — `/demo`
**Purpose:** the single-screen stage view: the unmodified Strike mandate detail sits beside a clearly labelled **Wavelength merchant simulator**. **The one thing:** the causal relationship is visible without tab switching — an operator moves the merchant price and the customer-facing timeline responds. The catalogue displays five products; AirPods Pro is visibly labelled as the only verified Prava checkout flow, while the other products are catalog context rather than unproven checkout claims.

### S0 · Setup — `/setup` (pre-demo only, never in the 3 minutes)
Passkey registration + Prava card-enrollment status + guardrail checklist (per-purchase approval OFF, wallet cap set). A literal pre-flight checklist UI — also our rehearsal tool.

## 5. Screen ↔ data (all served by Doc 4 queries)
S1→`POST draft`,`POST sign` · S2→`GET mandates`+events poll · S3→`GET mandates/:id`+events poll · S4→`GET receipt` · S5→store API · S0→webauthn + Prava list-cards. No screen needs data Doc 4 didn't already prove reachable.

## Assumptions

- **A1:** shadcn/ui primitives restyled by tokens above; no component library fighting.
- **A2:** No theme toggle, no responsive breakpoints below 1280 px — projector is the only client that matters (Doc 1 A1).
- **A3:** LLM narration appears as a one-line summary atop the Timeline ("Struck at $174, $6 under your cap, 41 h before expiry"), template-fallback if the LLM is slow (Doc 4 A4).
- **A4:** Wavelength product images: 2–3 CC0 photos, chosen at build, no design time spent.
